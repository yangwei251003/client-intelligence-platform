# 网站自带每日自动化：产品与实现契约

本契约约束使用 Skill 新做或改造的客户网站，不能仅以说明文档交付。以客户请求为准，可明确缩减需求；默认实现完整日更。网站包含前端、本地服务端、数据库和后台 Worker，不是只在浏览器打开时执行的静态页。

## 老板看到的流程

1. **说清关注什么**：行业/领域、关注对象、地区、include/exclude、语言、每日条数与阅读时间；预览应收录/排除的样例。
2. **系统推荐信息源**：网站展示匹配的主源、补充源、覆盖、免费条件与状态，默认选中核验通过且符合用途/预算的源。无 Key 的来源自动连接。不要要求老板提供 RSS 路由或 API 参数。
3. **一次连接摘要能力**：提供已实现并核实的供应商预设，预填服务端端点和兼容模型；客户在网站里完成受支持的授权或填 Key，点击连接并看到自检结果。没有免费模型额度就明确标价/待配置；不能自动充值，也不能悄悄使用开发者账号。
4. **选择每日时间**：显示客户时区、预计条数与用量、电脑需保持哪些服务运行；给出开始/暂停按钮、下一次时间。未配置好时明确具体缺项。
5. **每天直接读**：后台按时发布重点、最新与热门、当天概览与逐事件摘要。卡片有时间、来源、与老板的关系和“阅读原文”；页面打开期间通过 SSE/轮询获取新版本。

主界面使用业务语言。Base URL、原始 JSON、Cron、工作进程命令、日志目录放高级设置。帮助、失败提示和连接按钮直接带到本次需要的配置位置，不能只丢一个厂商文档首页。

## 自动选源与采集

开发时构建服务端 `SourceCatalog + SourceAdapter registry`：稳定 ID、领域/地区/语言标签、覆盖实体、类型/权限/配额、鉴权引用、最近核验、参数 schema、能力与备用源。交付资料中的 manifest 是其可审查快照，运行时由数据库管理状态，不硬编码在页面里。

网站把订阅映射为具体来源及查询条件，范围改动后重新计算覆盖；对支持的领域无需重新写页面或请老板选 API。新领域超出已验证目录时，显示未覆盖原因、已有相近源和“重新检测/补充来源”；可运行受限发现流程，但候选要通过 URL、内容、身份、访问条款与预算准入后才能启用。没有可用源时保留缺口，不能用模型编造 API 或通用新闻填满。

优先官方 API/RSS，其次经核验的官方网页。RSSHub 是可选适配器：核查实际路由、实例、鉴权、限制和上游站；公共实例和路由可能失效，自建也不赋予内容使用权或绕过权限。安装/托管按当前授权执行，不擅自公开部署。生产源须有真实探测与备用状态，不能把路由文档存在视为已接通。

每天一次为默认，采集频率服从每源配额与更新时间。确需更快时区分“增量采集频率”和“日报发布时间”，在预算内提高；不因 TXT 提到秒更就默认高频。使用 ETag/Last-Modified（源支持时）、游标与缓存，遵守 Retry-After；设置超时、并发、大小、格式上限、有限重试。403/验证码/许可变化时暂停该源、记录 partial，不能切换代理规避限制。已审核的备用源可以自动接替。

保存独立的源发布时间、首次发现时间、采集时间和事件变化时间。回填旧闻不算今天刚发生，发布时间未知显示 unknown；按客户时区决定日报日期，政策、论文和招标按其有效期与更新性质筛选。

## 去重、聚类与热度

分层处理：规范 URL/源内 ID 去重复抓取 → 规范化内容摘要 hash 检测同文 → 时间窗、实体与语义/相似度建立事件簇。不同报道属于同一事件时合并阅读卡片并保留独立证据，事件出现新事实时建立新版本与“最新变化”；不要把重复事件简单丢弃全部后续报道。

SimHash 可作为候选相似度筛选。距离阈值、文本长度、语种和时间窗须用客户领域样本校准；不能固定“距离 ≤ 3 就删除”或仅凭前 500 字决定重复。相同模板的不同采购项目、新日期/新数字/不同实体的新闻要保留。全库两两比较不可扩展时用分桶/索引；MVP 不必为此引入向量数据库。

最新排序依据可核实的发布时间/事件更新。热门排序只能使用有来源、有时间窗的信号：公开榜单名次/分数、可验证的互动量、去转载链后的独立来源覆盖数等。保存 `heatEvidence`（类型、来源 URL、观测时间、原始指标、范围）与置信度。没有指标时 `heat=unknown`，页面可按相关性/新鲜度补位，但不得把补位叫“最热”。

同一个源的多篇文章、一个通稿的多处转载不能冒充独立报道；多个来源提及表示“多源关注”，不证明受众热度或事实真实。相关性、质量、新鲜度和热度各自可解释，先归一化再可选加权；不要直接采用固定 0.4/0.6。关键词匹配足够时先做确定性订阅匹配，点击历史与协同过滤不是 MVP 必需。

## AI 概括、原文和发布

仅将允许读取的材料交给模型；标记全文、片段或仅元数据范围。输出当天领域概览和每事件的短概览、导读、关键事实、重要性、变化、局限及证据引用。用稳定输入 hash/版本缓存已生成摘要，重试有界；模型返回无效结构可有限修正，仍失败则保留上一版并报告失败，不用截断文字冒充 AI 总结。

日期、指标、URL、来源与“最热门”不可让模型猜。摘要长度是产品可读性预算，不是版权许可。默认展示必要标题、简短摘要、来源和原链；有授权才保留/展示全文或图片。仅保存封面 URL 也不意味着有图片展示许可，不默认盗链。不要硬性声称“少于100字即可合规”或“全文永远不能存”；具体保存范围按来源授权与客户需求处理。

原文保存经过验证的规范外链，浏览器使用安全 HTTP(S) 链接，在新标签页打开时加 `noopener noreferrer`。从 RSSHub/聚合器回溯原出处，付费墙原文可回链并标记访问限制，不能绕过。坏链接或来源不符要在验证阶段处理，不能伪造可打开。

发布只在事务内切换到完整的新 DailyEdition，并标记 full/partial/no_results；所有检索失败绝不写成 no_results。失败、限额或取消保留最近成功内容，并显示其真实日期。保留历史日报与运行记录，正文缓存、采集候选和日志可以分层设置保留期；不默认三天删历史。

## 持久调度与后台生命周期

默认单机独立 Worker + SQLite 持久作业。Next.js 页面/路由只保存设置、请求运行、读取状态；不要在页面、路由模块加载、热重载或多个 Next.js 进程里各建一个 cron。若选 OS 定时器适配器，网站仍须管理同一份时间/暂停设置并可实际生效，老板不写任务命令。

数据库记录 Schedule（enabled、timeZone、localTime、nextRunAt、revision、lastRunAt）、Job（dueAt、scheduleRevision、idempotencyKey、state、attempts、lease/heartbeat）与 RefreshRun（trigger、scheduledFor、阶段、结果）。等价结构可用，必须有原子 claim 与唯一幂等键，跨重启去重。Web/CLI/调度器共用锁，网络抓取和模型请求期间不长时间持有 SQL 写事务。

后台循环只负责唤醒检查，真正的到期状态保存在库里。支持暂停/恢复、改时区/时间后重算 nextRun、失效旧 revision；处理夏令时跳过/重复时刻并声明策略。漏跑默认合并为一次当前日报补跑，避免醒来补十天导致突发费用。Worker 崩溃按心跳与进程身份安全恢复，记录异常；不能因一个短超时抢走仍正常运行的锁。

本地启动器同时管理网站与 Worker，重复启动不增生进程。网站能展示 heartbeat、离线/待重连、下次计划、最近完成与失败原因。开机/登录自动启动由安装器按客户授权配置；断网有限重试、恢复补跑。更换目录、凭据失效或升级后自检，更新源码不属于日常资讯任务。

关闭浏览器不停止后台；退出后台服务、电脑关机或睡眠时不能保证准点执行。初次设置用简短人话说明，恢复后显示补跑状态。真正要求关机也准点，需要另行授权常开设备/服务器部署，不能靠文案承诺。

## 验收清单与证据字段

初始化工具生成 `automation-acceptance.json`。每项 status=pass 时保存实际证据路径；测试数据必须标模拟，最终真实验收不可由资料工具代替。

`automation.testEvidence` 必须指向按 `assets/scheduled-run-evidence.example.json` 格式导出的 JSON，分别从调度记录、RefreshRun、发布记录和浏览器观察取得数据。预检拒绝 manual 触发、run ID/日报 ID 不一致、时间顺序不成立、浏览器未在运行期间关闭以及普通文本冒充定时轨迹。预检无法认证记录真实，最终仍需对照真实运行日志；摘要/热度/原文各项证据须实际审阅，不能只看预检结果。

| 字段 | 必须观测到的行为 |
| --- | --- |
| guidedSetup | 新配置从网站完成范围、所选内容模式（AI模式连接模型预设）、时间与试运行；不需要手填 endpoint、改 .env 或写 Cron |
| sourceMatching | 新增/修改领域后匹配已测来源与参数；不支持领域显示覆盖缺口；无 Key 源自动连接 |
| secretStorage | 录入走受保护本机接口，存储受限，刷新/读取设置不回传 Key；日志/浏览器持久存储无秘密；更换端点不泄露旧 Key |
| backgroundSchedule | 使用测试时钟单测调度，并真实等待一个近期到期时间；trigger=scheduled 的 Run ID、退出状态与 DB 时间一致；网站暂停/改时间确实生效 |
| browserClosed | 浏览器全关期间到期任务仍完成；重新打开已出现新日报，无需手动更新 |
| restartCatchup | 中断 Worker/重启、错过时间、跨时区/DST、手动与定时碰撞不重复；恢复后按约定补跑一次 |
| automaticPublishing | 抓取→摘要→事务发布→打开的页面自动呈现新版本；失败保留上一版；partial/no_results 与全源失败区分 |
| modelSummaries | 对实际选中模型验证结构化摘要、关键事实/证据、当日概览、用量与无配置/限额/坏 JSON；模拟与真实测试分开 |
| dedupAndUpdates | 同文多 URL、同事件多源、新事实更新、同模板不同招标均按预期保留/合并；证据不丢失 |
| freshnessAndHeat | 旧文回填、未知日期、缺热度、单通稿多转载不冒充最新/最热；可追溯热度出处与时间窗 |
| originalLinks | 桌面/手机点击原文到对应真实出处；不指向聚合伪原文或不安全协议 |

纯手动需求可跳过后台调度四项；客户明确选择 raw 时跳过 modelSummaries 并用 rawFlowTest 验证。默认完整自动摘要网站不能跳过。`--ready` 仅预检这些资料条件，不证明真实通过。

## 对参考 TXT 的采用范围

采用定时流水线、RSS/API 优先、分层去重、兴趣与关注度结合、摘要回链。TXT 中难度倍数、100%通用、RSS免封禁、固定SimHash阈值、固定排名权重、固定三天清除和绝对版权结论均不能作为实现或验收依据。技术核查链接见信息源参考中的 RSSHub 补充条目；每次实现仍按所选版本官方文档验证。
